# Merchant OS — Agent Operating Rules

Before every Merchant OS task, read docs/agent-context/README.md and PROJECT_STATE.md, inspect the current commit and working-tree status, then read the relevant phase and decision records.

Keep project context current after every authorized phase: update PROJECT_STATE.md, the phase ledger, evidence, risks, and decisions as needed. Record exact commits, commands, environments, and results. A test name is not proof it passed; migration code is not proof it was applied; conversation-reported results remain UNVERIFIED until independently tied to evidence.

Classify statements as FACT, DECISION, PLAN, PROPOSAL, RISK, or UNVERIFIED. Preserve sources and contradictions. Never turn a plan or conversation suggestion into implementation authorization.

Approval-first boundaries: do not begin Phase 2E, change Commerce behavior, widen scope, or create/delegate to additional agents without explicit user approval. The present authorization covers context documentation only. Do not store secrets or customer personal information in these records.
